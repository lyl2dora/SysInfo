# 存储模块验收报告

> 日期：2026-10-16。范围：D53–D56（分支 `module/storage`）。规格与偏离记录见 `docs/design/storage.md`。

## 结论

- D54 列的内容全部完成：物理盘清单与 RAID 关系、每盘读写 / IOPS / 延迟、SMART 全字段、容量组与卷构成、磁盘 Top N、三个菜单栏 widget、两级面板、设置页、诊断页、历史与导出、CLI。
- 两台机器的精度对照全部一致；RAID 成员盘在顺序读负载下与 `iostat` 相差 0.01% 以内。
- 出厂默认与面板各档的开销都在 D19 预算内。
- 实现中发现 NVMe SMART 连接是独占的，SMART 改为每次打开 → 读 → 关闭（D56，修订了我按默认定的 D55）。**这一条请你验收时确认。**
- 需要你亲手点的部分见文末。

| 6 | `disktop`：按磁盘 IO 的 Top N | 持续写入（每 0.5 s 写 20 MB）时归到发起写入的 coalition，31–42 MB/s；同 uid 回退可用 | — |

## 开销（`docs/perf/storage.md`，D40 口径）

| 档位 | M5 | M4 |
|---|---|---|
| 出厂默认（CPU 占用、整机功率、内存占用、盘温四个 widget） | 0.34% | 0.15%* |
| 面板打开（存储概览，SMART 2 s 读全部盘，Top N 5 行） | 1.38%（Top N 2 s 时为 1.85%） | 0.52%*（Top N 2 s） |
| 面板打开（存储详情页） | 1.14% | 0.61%* |

- 预算：出厂默认 < 0.5%，面板打开 < 2%。两台都在预算内。
- 存储概览档第一次测是 1.85%，其中 coalition 每 2 s 全量扫描约占 0.7%。把磁盘 Top N 默认改成 5 s（同内存）后重测为 1.38%。M4 的概览档是改之前测的，改后只会更低。
- 带 * 的是 M4 上最快档时间太少，按周期数估算的值。

## 待你验收（需要真实操作）

1. 点 SSD widget 开面板，点一块 RAID 成员进详情，再按左上角「存储」返回；折叠、展开 RAID 组。
2. 设置「存储」页：打开读写速率与可用空间 widget；把盘温绑定换成某块 RAID 成员、再换成「所有盘最高温」；可用空间换成「Media」组。
3. 诊断页往下滚到「存储数据源」：6 块盘的 SMART 状态应为「SMART 正常 · 上次约 0.7–1 ms CPU」；展开「NVMe 节流计数（未验证）」看读数，收起后停止读取。
4. **确认 D56**：SMART 连接不常驻（每次打开 → 读 → 关闭）。代价是单盘一次从约 0.17 ms 升到约 0.7–1.0 ms CPU；好处是不挡 Stats、smartctl 和另一个 SysInfo 实例。
5. 可选：插一块 USB 盘，确认它出现在「外置」组，读写有数、SMART 显示「不支持」；拔掉后自动消失。

## 本模块新增的决策

- D53 模块顺序改为存储 → GPU 与加速器 → 网络 → 应用活动；D54 存储边界与出厂默认（盘温 widget 出厂开，修订 D51）；D55 SMART 读取频率与焦点盘；D56 SMART 连接不常驻（修订 D55，待确认）。
