# 功耗与散热模块验收报告

> 日期：2026-10-15 · 分支 `module/power-thermal` · 依据：功耗与散热模块设计 §1 验收清单、D44–D46
> 两台机器：M5 Pro（Mac17,16，开发机）与 M4 Pro（Mac16,11，对照机），系统都是 macOS 27.0.1 (26A434)。实测期间两台都没有运行 Stats。

## 结论

验收清单 9 项中，能由测试和实测确认的都已通过。有一项需要你判断：M4 上 **CPU tab** 面板档的开销按 D40 折算后超出 2%，见「开销」一节。它不是本模块造成的回退（原始 CPU 与 CPU 模块验收时相同），但按考核口径确实超了。

## 开销（`docs/perf/power-thermal.md`，D40 口径）

| 档位 | M5 等效最快档 | M5 原始 | M4 等效最快档 | M4 原始 | 预算 |
|---|---|---|---|---|---|
| 出厂默认（CPU 占用、整机功率两个 widget，历史与能耗开启） | 0.291% | 0.619% | 0.194%* | 0.811% | < 0.5% |
| 面板打开（功耗与散热 tab） | 1.240% | 1.657% | 0.752%* / 0.767%* | 2.963% / 3.005% | < 2% |
| 面板打开（CPU tab，对照） | 1.659% | 2.215% | **3.028% / 2.335%** | 3.779% / 3.800% | < 2% |

- \* 几乎全部跑在能效核上，按「周期数 ÷ 最快档顶档频率」估算（D40）。
- 本模块让常驻开销增加约 0.07（M5）个百分点（等效值）：后台每秒读一次整机功率（D46 的能耗积分），以及 SYS widget 每秒重绘。
- **CPU tab 在 M4 上**：原始 CPU 3.78–3.80%，与 CPU 模块验收时（3.81%）相同，工作量没变；但等效值这两次是 3.03% 和 2.34%，CPU 模块验收时是 1.58%。差别来自 D40 折算：这一档的最快档时间只占 2–3%，用这么少的样本估出的每秒指令数波动大。按考核口径它超出了 2%，需要你决定：接受（视为测量波动），还是另开一项继续优化 CPU tab 的开销。

## 待你验收（需要真实操作）

1. 点 SYS widget 打开面板、在两个 tab 之间切换、在设置里打开其余四个功耗 widget，看菜单栏宽度和数值。
2. 运行一段时间后看面板「最近 30 分钟」卡片（开机后约每 30 分钟一批，app 要在批次边界前后都在运行）。
3. 诊断页展开「传感器目录」，看分组和占位值是否合理。

## 本模块新增的决策与主要偏离

- D44–D46 见 `docs/decisions.md`。
- 偏离记录在 `docs/design/power-thermal.md` 文末，主要有：档案 system 段去掉 `pmgrClusters`；补数按分钟存；遥测第一段只建基线；app 层通用化（`MenuWidget`、`StatusItemView`、`AppServices`、`HistoryChart`）。
- 自查中发现并已修正：面板在异步卡片加载后没有重新量高度（内容被裁）；`--open-panel` 启动时风扇行缺失；第一段遥测对账偏差 −8.4%；空闲时 GPU 交叉核对可能误判。
