# 桌面小组件充实（甲 + 乙）

> 日期：2026-10-21 · 状态：**试做中**（用户 2026-10-21：「先做甲和乙，看看效果」）；看过效果后拍板，结论追加为 D94 · 分支：`module/widgets-rich`
> 在 D90、D91 之上改：仍是一个「总览」组件、内容固定（WS2 不变）；改的是各尺寸放什么、怎么画，以及快照里多带哪些数。

## 1. 问题

D91 的各尺寸只有「标签 + 数字」：小号两个数、中号四个数，曲线只在大号以上出现。桌面组件比菜单栏多出来的是面积，这块面积没用上；每个数也缺上下文（内存占用不带容量与压力，CPU 不分档，没有 GPU）。

## 2. 甲：画法

| 尺寸 | 内容 |
|---|---|
| 小 | 2×2 圆环：CPU、GPU、内存、启动盘已用；环内是百分比 |
| 中 | 2×2 卡片：CPU、GPU、内存、功率。每张卡：标签、大数字、一行副信息，底下垫一条 24 h 曲线（面积图，低不透明度） |
| 大 | 中号四张卡（加高）+ CPU 按档占用条（档名运行时取，D20）+ 两列明细：下载、上传、SoC 温度、风扇（有风扇时）、盘温、启动盘可用（带容量条） |
| 超大竖版 | 大号全部 + 四张带标注的 24 h 曲线：CPU、GPU、功率、SoC 温度；每张标最低 / 平均 / 最高和时间刻度（−24 h、−12 h、现在） |

副信息：

- CPU：各档占用，例如「超级核 42% · 性能核 8%」；
- GPU：GPU 功率（AGX，D44）；
- 内存：「已用 / 总量 · 压力」，有交换时再加交换；
- 功率：SoC 热点温度，有风扇时加转速。

渲染模式：桌面上是 accented（probe A）。环、条、曲线的填充部分 `widgetAccentable`，底轨用次要色；不靠色相区分高低。fullColor 下档条沿用面板的档颜色（D29）。

## 3. 乙：快照 v3

- 新槽位：`gpuUsage`、`gpuPower`、`memoryUsed`、`memoryTotal`、`memoryPressure`、`swapUsed`、`fanSpeed`、`bootDiskFree`、`bootDiskTotal`。
  - `fanSpeed` 取所有风扇的最高转速；没有风扇的机器不写这一项（不是「不可用」，是不适用）。
  - 启动盘容量取启动容量组（与菜单栏「可用空间」widget 的默认绑定相同），快照里只放数值，不放组的键（D22）。
- 按档占用：新字段 `cpuLevels`，每档写本地化后的档名、原始档名（取颜色用）、占用与数据质量。档数运行时发现，不写死（D20）。
- 带曲线的槽位：CPU、GPU、内存、功率、SoC 热点（多了 GPU）。五条 × 288 点，快照约 30 KB，读取仍在 1 ms 量级（probe D）。
- 版本升到 3；扩展读到 v2 时当作「没有快照」，留标记让主 app 立刻补写一份 v3。

## 4. 开销

- 写入器的后台需求多了三个采集器：`power.gpu`（GPU 占用与功率）、`storage.capacity`（启动盘容量）；风扇来自已有的 `power.sensors`。节奏不变（出厂 5 分钟）。
- 没有组件放置时与原来相同（不登记需求）。放置后的增量待 `make measure` 实测。

## 5. 待拍板

看过效果后定：各尺寸的取舍（尤其小号放不放温度或功率）、中号卡片底下的曲线跨度（24 h 还是最近 1 h）。
