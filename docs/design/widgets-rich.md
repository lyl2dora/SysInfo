# 桌面小组件充实（甲 + 乙）

> 日期：2026-10-21 · 状态：**已拍板**（D94） · 分支：`module/widgets-rich`
> 在 D90、D91 之上改：仍是一个「总览」组件、内容固定（WS2 不变）；改的是各尺寸放什么、怎么画，以及快照里多带哪些数。

## 1. 问题

D91 的各尺寸只有「标签 + 数字」：小号两个数、中号四个数，曲线只在大号以上出现。桌面组件比菜单栏多出来的是面积，这块面积没用上；每个数也缺上下文（内存占用不带容量与压力，CPU 不分档，没有 GPU）。

## 2. 甲：画法

| 尺寸 | 内容 |
|---|---|
| 小 | 2×2 圆环：CPU、GPU、内存、磁盘已用（盘温那块盘所在的容量组）；环内是百分比 |
| 中 | 2×2 卡片：CPU、GPU、内存、功率。每张卡：标签、大数字、一行副信息，底下垫一条 24 h 曲线（面积图，低不透明度） |
| 大 | 中号四张卡（加高）+ CPU 按档占用条（档名运行时取，D20）+ 明细三行：下载 / 上传 / 交换；盘温（带盘名）；容量组名、容量条与可用 |
| 超大竖版 | 大号全部 + 四张带标注的 24 h 曲线：CPU、GPU、功率、SoC 温度；每张标最低 / 平均 / 最高，竖线每 6 h 一条 |

副信息：

- CPU：各档占用，例如「超级核 42% · 性能核 8%」；
- GPU：GPU 功率（AGX，D44）；
- 内存：「已用 / 总量 · 压力」（交换在大号起的明细里）；
- 功率：SoC 热点温度，有风扇时加转速。

渲染模式：桌面上是 accented（probe A）。环、条、曲线的填充部分 `widgetAccentable`，底轨用次要色；不靠色相区分高低。fullColor 下档条沿用面板的档颜色（D29）。

## 3. 乙：快照 v3

- 新槽位：`gpuUsage`、`gpuPower`、`memoryUsed`、`memoryTotal`、`memoryPressure`、`swapUsed`、`fanSpeed`、`diskFree`、`diskTotal`；`bootDiskTemperature` 改名 `diskTemperature`。
  - `fanSpeed` 取所有风扇的最高转速；没有风扇的机器不写这一项（不是「不可用」，是不适用）。
- **盘跟随菜单栏设置**（2026-10-21 用户确认，取代 D91 / `widgets.md` §3「盘温取启动盘所在的盘」）：
  - 盘温跟随菜单栏盘温 widget 的 `diskTemperatureTarget`，解析与菜单栏、面板总览相同。
  - 容量（大号起的容量行、小号的「磁盘」圆环）跟着盘温那块盘走，不看可用空间 widget 的 `diskFreeTarget`（同日用户改定：两行挨着，应当说的是同一块盘）。物理盘本身没有容量，按归属找容量组：RAID 成员取所属的 RAID 组，其余取以它为载体的组；有多个时取非辅助组里最大的；盘上没有挂载的组时显示「—」。
  - 「所有盘最高温」：取各盘读数的最大值（与菜单栏相同），并写出那块盘的名字；最热的盘变了，名字与容量行一起跟着变。
  - 新字段 `diskName`（盘的显示名：型号，RAID 成员为「成员 n · 型号」）与 `diskGroupName`（容量组名）。只放显示名，不放盘与组的键、序列号（D22）；组容器受 TCC 保护、只在本机。
  - 改了盘温的目标，主 app 立刻补写一份快照。
- **功率取平滑值**（同日用户确认）：整机与 GPU 功率用菜单栏同一份 EMA（K24）。菜单栏在采样时两边一致；只有小组件在采样时间隔远超时间常数，平滑值等于原始值。
- 按档占用：新字段 `cpuLevels`，每档写本地化后的档名、原始档名（取颜色用）、占用与数据质量。档数运行时发现，不写死（D20）。
- 带曲线的槽位：CPU、GPU、内存、功率、SoC 热点（多了 GPU）。五条 × 288 点，快照约 30 KB，读取仍在 1 ms 量级（probe D）。
- 版本升到 3；扩展读到 v2 时当作「没有快照」，留标记让主 app 立刻补写一份 v3。

## 4. 开销

- 写入器的后台需求多了两个采集器：`power.gpu`（GPU 占用与功率）、`storage.capacity`（容量组）；风扇来自已有的 `power.sensors`。节奏不变（出厂 5 分钟）。
- 没有组件放置时与原来相同（不登记需求）。
- 扩展进程（2026-10-21 实测，`docs/perf/widgets.md`）：四种尺寸各放一个，1 分钟节奏约 0.82% 单核（原版 0.43%），折算 5 分钟约 0.16%；每个组件每次重绘约 120 ms，多出来的主要是曲线（四种尺寸合计 6 张 → 17 张）。
  - 曲线随后全部改用 `Path` 自绘、不再用 Swift Charts（用户同日要求先压开销）：1 分钟节奏降到约 0.29% 单核，折算 5 分钟约 0.06%，低于原版。设置页说明为约 0.1% / 0.3%。
- 「所有盘最高温」本来就让 SMART 读全部盘（D55，由菜单栏设置决定），小组件跟随它不增加读取。

## 5. 实测（2026-10-21，本机 M5）

- 超大竖版实拍：盘温跟随设置里选的 RAID 成员盘（与 CLI 读数一致），容量行显示组名；临时把 Dev 的盘温目标改为「所有盘最高温」，组件换成内置盘与其温度，测完已恢复原设置。
- 小、中、大：用户放到桌面后实拍，四种尺寸都没有超出边界。
- 容量跟随盘温那块盘：选 RAID 成员盘时容量行显示该 RAID 组（可用 35.0 TB），小号「磁盘」圆环同步变化。
- M4（2026-10-21，同一份 Developer ID 签名的 Debug 构建，`--factory-defaults`，用户屏幕共享放了四种尺寸）：渲染正常；档名为「性能核 / 能效核」；风扇 999 rpm、盘温 37°、可用 827 GB、整机 9.9 W，与 CLI（1001 rpm、38 °C、826.6 GB、9.93 W）一致；曲线因临时历史库刚建几乎为空（预期）。`make remote-test` 380 个通过。起初图库里没有组件，原因与绕法见 D94「开发陷阱」。用完已清场，桌面上的四个组件请用户删除。

## 6. 结论

已按 D94 拍板：卡片底下用 24 h 曲线；小号保持四个圆环。
