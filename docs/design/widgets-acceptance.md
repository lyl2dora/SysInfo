# 桌面小组件模块验收报告

> 日期：2026-10-21。范围：D87、D90、D91（分支 `module/widgets`，已合入 `main` 到 D93）。能力边界与探针结果见 `widgets-boundary.md`，规格与进度见 `widgets.md`，开销见 `docs/perf/widgets.md`。

## 结论（待用户验收）

- D90、D91 列的内容已完成：
  - 扩展 `SysInfoWidgets`（沙盒，只链接 SysModel，碰不到私有层）：一个「总览」组件，小 / 中 / 大 / 超大竖版四种尺寸，内容按 WS1 固定（`StaticConfiguration`，WS2）；
  - 主进程写快照（v2，组容器 `widget-snapshot.json`，原子写入），只在有组件放置时登记后台需求、写文件、刷新组件；
  - 组件上的刷新按钮：`RefreshWidgetIntent` 在主进程执行，现采一次再写；
  - SysInfo 没在运行时保留最后的数据并变暗，注明「未运行」与时间（WS3）；正常退出时立即写一份 `appRunning = false`；
  - 设置新开侧栏页「桌面小组件」（刷新节奏 5 / 1 分钟并标注开销、已放置的组件、最近写入时间、放置说明，WS4）；隐私页「数据存放」加组容器一行（W6）；
  - 构建与发布：`check-private-imports.sh` 扫描 `Widgets/`；`build-release.sh` 检查嵌入的 `.appex` 存在并一起签名、核对其 entitlements；`stop-dev.sh` 一并结束 Debug 扩展；`remote-app.sh` 同步扩展目录到对照机。
- 两台机器的扩展侧验证都通过（§1）；出厂默认与面板两档在 M4 复测通过预算（§2）。
- 探针清理：probe B 已停掉并注销；桌面上的两个探针组件（SysInfo Probe Dev / Rel）用户已于 2026-10-21 手动删掉。本机两个探针的组容器还在（受 TCC 保护，没从终端删），不影响正式组件。
- 偏离规格 6 处，均为细节，见 §3。
- 验收中需要用户确认或补测的项目见 §4。

## 3. 偏离规格

1. **「想要数据」标记每 30 s 查一次**（规格 §4.1 写的是随 5 分钟的配置检查顺便看）：只是一次文件读取，换来刚放上组件 30 s 内就出数据。
2. **启动后等第一批样本再写**（最多 10 s）：否则第一份快照会把还没采到的项写成不可用（9c4a9d7）。
3. **当前值的陈旧阈值是「节奏 + 30 s」**（规格 §4.2 写的是「比节奏还旧」）：留出轮询粒度的余量，避免恰好在边界上的样本被误判。
4. **曲线退回内存缓冲的条件放宽为「历史库没有数据」**（规格 §4.3 写的是历史记录关闭时）：历史开着但刚启动、库里还没有这一项时也能画出最近 15 分钟（1 分钟一个点）。组件上「历史记录已关闭」的注明仍只在 CPU、功耗、内存三项历史任一关闭时出现。
5. **曲线点数不足两个时显示「暂无数据」**：`--factory-defaults` 用临时历史库，每次启动头 5–10 分钟都是这样，属预期。
6. **测量副本改用 `.dev.measure` 标识**（558fc70）：否则会和桌面上 Debug 版的扩展抢 LaunchServices 登记（probe A：同一 bundle ID 只认一份）。

## 4. 待用户验收与已知问题

需要用户点按确认（D18：真实点击由用户验收）：

1. 放置与删除：在桌面右键「编辑小组件」放上 / 删掉「SysInfo Dev 总览」，设置页「桌面小组件」的已放置列表跟着变，全部删掉后不再写快照。
2. 历史关闭时的曲线降级：在「历史与导出」关掉 CPU 历史，大号曲线标题变为「15 分钟（历史记录已关闭）」。
3. 锁屏后解锁：组件数据在解锁后是新的（chronod 在锁屏、显示器睡眠期间是否刷新没测过，边界文档 §5）。
4. Debug 与 Release 并存：两份各自的组件互不串数据（组容器不同）。M4 上实际并存运行过，曾因 SMART 抢占出现「—」（已由 D93 修复）。

已知问题（不阻塞验收，记下待观察）：

1. **app 放在 `/tmp` 下时刷新按钮无效**：linkd 给 App Intents 建索引时找不到 app（-10814）。拷到 `~/Applications` 后正常；正式版装在 `/Applications` 不受影响。从「下载」直接打开、被 App Translocation 挪到临时路径运行时可能也受影响，未验证。
2. **主进程没在运行时点刷新**：`.main` 的 intent 会不会拉起 SysInfo 还没专门测过（边界文档 §3）。
3. **一次被系统重新拉起**：M4 上结束 `/tmp` 下的实例后，launchd 以「launch job demand」立即重新拉起了它，原因未查明，之后两次没复现。如果复现，要查是不是 App Intents 的连接导致。
4. **对照机清场缺口**：扩展的沙盒容器 `~/Library/Containers/<app>.widgets`（以及 `.measure.widgets`、`.probe.widgets`）不在 `remote-app.sh` 的痕迹清单里，M4 上三个都还在（D39）。
