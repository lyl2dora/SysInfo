# 内存模块验收报告（含 D48 单实例）

> 日期：2026-10-16。范围：D48（单实例，分支 `fix/single-instance`）、D49–D51（内存模块，分支 `module/memory`，基于前者）。
> 规格与偏离记录见 `docs/design/memory.md`。

## 结论

- D49 列的内容全部完成。
- 两台机器的精度对照全部一致。
- 出厂默认与面板档的开销都在 D19 预算内。
- 需要你亲手点的部分见文末。

## 开销（`docs/perf/memory.md`，D40 口径）

| 档位 | M5 | M4 |
|---|---|---|
| 出厂默认（CPU 占用、整机功率、内存占用三个 widget，D51） | 0.41% | 0.23%* |
| 面板打开（内存 tab，Top N 5 行） | 1.12% | 0.55%* |

- 预算：出厂默认 < 0.5%，面板打开 < 2%。两台都在预算内。
- M5 出厂默认档比功耗模块验收时（两个 widget，0.29%）高了约 0.11%。其中内存 widget 与后台内存历史的采样本身约 0.03%（`memory.vm` 一次约 0.3 ms），其余是多一个 widget 的重绘与测量波动。
- 带 * 的是 M4 上最快档时间太少，按周期数估算的值。

## 留待后续优化

- 面板卡片底部的注释（内存构成、功耗分解都是）用的是 tertiary 文字色，在深色壁纸上几乎看不见。要不要统一改成 secondary，等你看过再定。

## 待你验收（需要真实操作）

1. 点 MEM widget 开面板；展开 Top N 组行，结束一个自己启动的测试进程（按住 ⌥ 时默认强制）。
2. 设置「内存」页：打开压力、Swap widget，把占用切成 GB；Top N 改成按进程、改行数。
3. 诊断页往下滚到「内存数据源」，展开「DRAM 带宽（估算）」，看读写数值，收起后需求应注销（诊断页「有效需求」里的 `memory.bandwidth` 消失）。
4. 单实例：日用版装好后，再双击 `build/` 下的 Release 副本，应该只弹出已运行实例的设置窗口，不出现第二套 widget（或者用 Debug 版加 `--single-instance` 试）。

## 本模块新增的决策

- D48 单实例；D49 内存边界；D50 合并模式改期；D51 首次启动默认开三个 widget（关闭 K41）；D52 内存压力验证的 sudo 例外。
- 2026-10-16 用户手测第 1–4 项，未发现问题；压力等级随后按 D52 用模拟压力验证（第 8 项）。
- 压力验证时你从 Xcode 启动的 SysInfo Dev（build 1）持有单实例锁，我用 `make run` 启动的实例按 D48 作为从实例运行、改用临时历史库，正好在真实场景里印证了 D48 的 Debug 规则。
