# 合并模式：面板结构与长清单（设计稿）

> 日期：2026-10-17。§2–§6 的长清单形态已由用户确认（「应用活动主体用独立窗口，面板里只放入口；其余几点按你的建议走」），见 `docs/decisions.md` D64，关闭 K54。
> 合并为单个 item 本身（K43 点击行为、总览 tab 内容、模块切换器样式）在 §7 列为待定，开工实现前再与用户讨论。

## 1. 长清单盘点

按 2026-10-17 的代码（`App/Panel/*`）与 D31、D54、D57、D60、D63 盘点：

| 清单 | 数量级 | 改版前的做法 | 性质 |
|---|---|---|---|
| 网络·虚拟接口 | 0–20+（M5 15 个，M4 9 个） | 就地展开，可能超出屏幕 | 实体组 |
| 网络·物理接口 | 1–4 | 直接列出 | 少量，不动 |
| 存储·盘 | 1–10+（M5 含 RAID 与外置） | 超过 7 块在限高区内滚动 | 实体组 |
| 存储·RAID 成员 / 容器内的卷 | 2–8 / 5–10 | 就地展开，记住展开状态 | 实体组的下一层 |
| Top N（CPU、内存、GPU、磁盘） | 3–10 行，定高 | coalition 就地展开，最多 8 个成员 +「其余」 | 排行 |
| CPU 每核 | 14–18，Ultra 最多 32 | 按簇自绘柱条，高度由拓扑决定 | 结构图，不是清单 |
| 功耗·30 分钟批次 | 约 10 行，固定 | 直接列出 | 少量，不动 |
| 应用活动·应用排行 | 全部 coalition 300–800 | — | 探索型多列表格 |
| 应用活动·单应用成员 | 可达 50+（浏览器、Xcode） | — | 实体组 |
| 应用活动·电源断言 | 5–20 | — | 实体组 |
| 应用活动·时间段排行（含已退出的应用） | 几十到上百 | — | 历史排行 |
| P1·每应用网络 | 同应用排行 | — | 应用排行的一列 |

按性质分四类，各用一种形态：实体组 → 汇总行 + 二级列表页（§2、§3）；排行 → 定高 Top N + 应用详情页 + 跳转应用活动（§4）；结构图 → 不动（§5）；探索型表格 → 独立窗口（§6）。

## 2. 模块主页定高

- 模块主页上每一节的高度不随实体数量变化，只随模块自身的设置（Top N 行数、是否拆分用户 / 系统等）变化。
- 允许就地展开的只有**数量固定且不超过约 5 行**的内容：CPU 详情、RAID 成员（成员数随阵列固定）、诊断类折叠块。
- 数量不封顶的组，在主页上折成一行**汇总行**，右侧带 `›`，点击推入二级列表页（§3）：
  - 网络虚拟接口：`虚拟接口 15 个 · 3 个有流量 ›`。按 D60 虚拟接口不能相加，汇总行只给个数和活跃数，不给合计速率。
  - 存储外置盘：内置盘始终单独列出；外置盘不超过阈值（暂定 2 块）时直接列出，超过时折成 `外置 6 块 · 最高 45 °C · 读 120M 写 3M ›`。读写合计只在同一组的物理盘之间相加（D54：RAID 不合计，成员盘各算各的，这里是按盘相加，不涉及阵列）。阈值在实现时按 1080p 实测再定。
  - RAID 组：组标题照旧显示阵列状态；成员少于等于 5 块时就地展开（D54 的做法），超过时同样折成汇总行。
- 主页不再有嵌套的滚动区；存储原来「超过 7 块盘在限高区滚动」的做法取消。
- 好处：主页高度只由模块决定，D47 遗留的「模块高度不一致导致闪烁」只剩模块之间的差异（§7）。

## 3. 二级页：面板内推入

- 形态：沿用存储单盘详情的原地切换（D47、D54）。宽度仍为 360 pt，顶栏左侧「返回」，Esc 也返回。
- 不做并排的第二个面板：
  - widget 多在屏幕右侧，并排只能往左弹，位置随 widget 变化；
  - non-activating 面板再加一个玻璃窗口，会重新引入 27 上的窗口切换闪烁（调研报告 §2.2）；
  - 浮窗模式下要同时管理两个窗口的锚点、关闭与固定。
- 列表页：
  - 顶部可带「只看活跃 / 显示全部」切换。虚拟接口与外置盘默认只看活跃（最近 60 s 有流量或读写）。切换状态按列表记住。
  - 排序固定（名称或 index），不按实时数值排序，避免行跳动；活跃项用强调色标出。
  - 高度取「内容高度」与「屏幕可用高度 − 边距」的较小值，超出部分只在这一页内滚动。
- 层级最多两层：模块主页 → 列表页 → 单项详情页（如单盘详情、应用详情）。
- 导航规则：
  - 再次点击同一个 widget：回到该模块主页（面板已显示该模块的二级页时），面板不关闭；在主页时照旧关闭面板。
  - 点击另一个模块的 widget：换成那个模块的主页，不保留原模块的层级。
  - 固定为浮窗时保留当前层级。
  - 二级页需要的数据照常按可见性登记需求（只在页面可见时采样）。

## 4. Top N 与应用详情页

- 各模块的 Top N 保持定高（0 / 3 / 5 / 8 / 10 行，设置不变）。
- **取消 coalition 就地展开**。点击某一行推入**应用详情页**：
  - 成员进程列表（可滚动），每个成员显示当前模块的指标；
  - 结束进程按钮，规则照 D31（同 uid、先确认、按住 ⌥ 强制、组行与 root 进程不显示）；
  - 该应用在各域的当前值（CPU、内存、GPU、ANE、磁盘、能耗），面板可见期间按 coalition 扫描读取；
  - 应用活动上线后补上该应用的历史曲线。
- 应用详情页是**一个通用组件**：CPU、内存、GPU、存储四处 Top N 与应用活动窗口共用，只是排布不同（面板里纵向堆叠，窗口里放在表格旁）。
- Top N 底部加一行「在应用活动中查看全部 ›」：打开应用活动窗口，按该模块对应的列排序。
- 宿主 coalition（终端、Xcode）照 D31 保持一行、副标题显示占比最高的成员；详情页里列全部成员。
- 「按进程」分组模式下行就是进程，点击不推入详情页，只保留结束按钮。

## 5. CPU 每核不属于长清单

- 每核柱条按簇自绘，高度由拓扑决定，32 核时柱条变细，行数不增加。不改。

## 6. 应用活动：独立窗口为主体，面板只放入口

取代 D21 中「『应用活动』是其中一个 tab」。

- **窗口**：标准、可缩放的 `NSWindow` + SwiftUI `Table`。
  - 左侧：时间段（现在 / 1 小时 / 今天 / 7 天）与分类（全部应用 / 阻止睡眠 / 唤醒最多，分类在应用活动开工时定）。
  - 右侧：多列表格（CPU、内存、能耗、GPU、ANE、磁盘读写，P1 加网络），列可排序、可隐藏，支持搜索；历史时段包含已退出的应用。
  - 选中一行，在表格旁显示应用详情（§4 的同一组件）。
  - 窗口可见时才采样（coalition 扫描约 2.8 ms / 次，间隔在应用活动开工时定）；关闭窗口即停。
- **面板入口**：
  - 合并模式的总览 tab 放一张「当前最耗能的 3 个应用」卡片，点击打开窗口；
  - 各模块 Top N 底部的「在应用活动中查看全部 ›」（§4）；
  - 顶栏的「活动监视器」按钮保留；是否另加「应用活动」按钮在实现时看顶栏空间。
- 应用活动不占菜单栏 widget（K40 原推荐不变）。
- 窗口的列、时间段、分类、采样间隔、电源断言等能力边界，在应用活动模块开工时与用户讨论。

## 7. 与合并模式的配合（部分待定）

已定：
- 模块切换器只在模块主页出现；进入二级页后顶栏换成「返回 + 标题」。
- 模块之间的高度差：内容已顶部对齐，改高时只有底边移动，加一段短过渡（约 0.15 s）。不取各模块最大高度（内存等短模块会留下大片空白）。
- 总览卡片点击后**替换**为该模块主页，不算一层，避免出现总览 → 模块 → 列表 → 详情四层。

待定（合并模式开工时再讨论）：
- K43：合并 item 点击后打开总览还是按点击位置打开对应模块。
- 总览 tab 各模块卡片的内容。
- 模块切换器的样式与排序（是否跟随菜单栏 widget 顺序）。
- 合并与单 widget 模式的设置组织（D41 的「菜单栏」容器页）。

## 8. 对现有模块的改动清单

| 模块 | 改动 |
|---|---|
| 网络 | 虚拟接口改为汇总行 + 列表页（解决 D63 的已知问题） |
| 存储 | 外置盘超过阈值折成汇总行 + 列表页；取消限高滚动；RAID 成员超过 5 块折叠 |
| CPU、内存、GPU、存储 | Top N 取消就地展开，点击行推入应用详情页；底部加「查看全部」入口（应用活动上线前先隐藏或置灰） |
| 面板外壳 | 推入式导航栈（两层）、返回 / Esc、再次点击回主页、改高过渡 |
| CPU 每核、功耗 | 不改 |
