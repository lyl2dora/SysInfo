# 合并模式：面板结构与长清单（设计稿）

> 日期：2026-10-17。§2–§6 的长清单形态已由用户确认（「应用活动主体用独立窗口，面板里只放入口；其余几点按你的建议走」），见 `docs/decisions.md` D64，关闭 K54。
> 合并为单个 item 本身见 §7（MG1–MG6），见 D65，关闭 K43。

## 1. 长清单盘点

按 2026-10-17 的代码（`App/Panel/*`）与 D31、D54、D57、D60、D63 盘点：

| 清单 | 数量级 | 改版前的做法 | 性质 |
|---|---|---|---|
| 网络·虚拟接口 | 0–20+（M5 15 个，M4 9 个） | 就地展开，可能超出屏幕 | 实体组 |
| 网络·物理接口 | 1–4 | 直接列出 | 少量，不动 |
| 存储·盘 | 1–10+（M5 含 RAID 与外置） | 超过 7 块在限高区内滚动 | 实体组 |
| 存储·RAID 成员 / 容器内的卷 | 2–8 / 5–10 | 就地展开，记住展开状态 | 实体组的下一层 |
| Top N（CPU、内存、GPU、磁盘） | 3–10 行，定高 | coalition 就地展开，最多 8 个成员 +「其余」 | 排行 |
| CPU 每核 | 14–18，Ultra 最多 32 | 按簇自绘柱条，高度由拓扑决定 | 结构图，不是清单 |
| 功耗·30 分钟批次 | 约 10 行，固定 | 直接列出 | 少量，不动 |
| 应用活动·应用排行 | 全部 coalition 300–800 | — | 探索型多列表格 |
| 应用活动·单应用成员 | 可达 50+（浏览器、Xcode） | — | 实体组 |
| 应用活动·电源断言 | 5–20 | — | 实体组 |
| 应用活动·时间段排行（含已退出的应用） | 几十到上百 | — | 历史排行 |
| P1·每应用网络 | 同应用排行 | — | 应用排行的一列 |

按性质分四类，各用一种形态：实体组 → 汇总行 + 二级列表页（§2、§3）；排行 → 定高 Top N + 应用详情页 + 跳转应用活动（§4）；结构图 → 不动（§5）；探索型表格 → 独立窗口（§6）。

## 2. 模块主页定高

- 模块主页上每一节的高度不随实体数量变化，只随模块自身的设置（Top N 行数、是否拆分用户 / 系统等）变化。
- 允许就地展开的只有**数量固定且不超过约 5 行**的内容：CPU 详情、RAID 成员（成员数随阵列固定）、诊断类折叠块。
- 数量不封顶的组，在主页上折成一行**汇总行**，右侧带 `›`，点击推入二级列表页（§3）：
  - 网络虚拟接口：`虚拟接口 15 个 · 3 个有流量 ›`。按 D60 虚拟接口不能相加，汇总行只给个数和活跃数，不给合计速率。
  - 存储外置盘：内置盘始终单独列出；外置盘不超过阈值（暂定 2 块）时直接列出，超过时折成 `外置 6 块 · 最高 45 °C · 读 120M 写 3M ›`。读写合计只在同一组的物理盘之间相加（D54：RAID 不合计，成员盘各算各的，这里是按盘相加，不涉及阵列）。阈值在实现时按 1080p 实测再定。
  - RAID 组：组标题照旧显示阵列状态；成员少于等于 5 块时就地展开（D54 的做法），超过时同样折成汇总行。
- 主页不再有嵌套的滚动区；存储原来「超过 7 块盘在限高区滚动」的做法取消。
- 好处：主页高度只由模块决定，D47 遗留的「模块高度不一致导致闪烁」只剩模块之间的差异（§7）。

## 3. 二级页：面板内推入

- 形态：沿用存储单盘详情的原地切换（D47、D54）。宽度仍为 360 pt，顶栏左侧「返回」，Esc 也返回。
- 不做并排的第二个面板：
  - widget 多在屏幕右侧，并排只能往左弹，位置随 widget 变化；
  - non-activating 面板再加一个玻璃窗口，会重新引入 27 上的窗口切换闪烁（调研报告 §2.2）；
  - 浮窗模式下要同时管理两个窗口的锚点、关闭与固定。
- 列表页：
  - 顶部可带「只看活跃 / 显示全部」切换。虚拟接口与外置盘默认只看活跃（最近 60 s 有流量或读写）。切换状态按列表记住。
  - 排序固定（名称或 index），不按实时数值排序，避免行跳动；活跃项用强调色标出。
  - 高度取「内容高度」与「屏幕可用高度 − 边距」的较小值，超出部分只在这一页内滚动。
- 层级最多两层：模块主页 → 列表页 → 单项详情页（如单盘详情、应用详情）。
- 导航规则：
  - 再次点击同一个 widget：回到该模块主页（面板已显示该模块的二级页时），面板不关闭；在主页时照旧关闭面板。
  - 点击另一个模块的 widget：换成那个模块的主页，不保留原模块的层级。
  - 固定为浮窗时保留当前层级。
  - 二级页需要的数据照常按可见性登记需求（只在页面可见时采样）。

## 4. Top N 与应用详情页

- 各模块的 Top N 保持定高（0 / 3 / 5 / 8 / 10 行，设置不变）。
- **取消 coalition 就地展开**。点击某一行推入**应用详情页**：
  - 成员进程列表（可滚动），每个成员显示当前模块的指标；
  - 结束进程按钮，规则照 D31（同 uid、先确认、按住 ⌥ 强制、组行与 root 进程不显示）；
  - 该应用在各域的当前值（CPU、内存、GPU、ANE、磁盘、能耗），面板可见期间按 coalition 扫描读取；
  - 应用活动上线后补上该应用的历史曲线。
- 应用详情页是**一个通用组件**：CPU、内存、GPU、存储四处 Top N 与应用活动窗口共用，只是排布不同（面板里纵向堆叠，窗口里放在表格旁）。
- Top N 底部加一行「在应用活动中查看全部 ›」：打开应用活动窗口，按该模块对应的列排序。
- 宿主 coalition（终端、Xcode）照 D31 保持一行、副标题显示占比最高的成员；详情页里列全部成员。
- 「按进程」分组模式下行就是进程，点击不推入详情页，只保留结束按钮。

## 5. CPU 每核不属于长清单

- 每核柱条按簇自绘，高度由拓扑决定，32 核时柱条变细，行数不增加。不改。

## 6. 应用活动：独立窗口为主体，面板只放入口

取代 D21 中「『应用活动』是其中一个 tab」。

- **窗口**：标准、可缩放的 `NSWindow` + SwiftUI `Table`。
  - 左侧：时间段（现在 / 1 小时 / 今天 / 7 天）与分类（全部应用 / 阻止睡眠 / 唤醒最多，分类在应用活动开工时定）。
  - 右侧：多列表格（CPU、内存、能耗、GPU、ANE、磁盘读写，P1 加网络），列可排序、可隐藏，支持搜索；历史时段包含已退出的应用。
  - 选中一行，在表格旁显示应用详情（§4 的同一组件）。
  - 窗口可见时才采样（coalition 扫描约 2.8 ms / 次，间隔在应用活动开工时定）；关闭窗口即停。
- **面板入口**：
  - 合并模式的总览 tab 放一张「当前最耗能的 3 个应用」卡片，点击打开窗口；
  - 各模块 Top N 底部的「在应用活动中查看全部 ›」（§4）；
  - 顶栏的「活动监视器」按钮保留；是否另加「应用活动」按钮在实现时看顶栏空间。
- 应用活动不占菜单栏 widget（K40 原推荐不变）。
- 窗口的列、时间段、分类、采样间隔、电源断言等能力边界，在应用活动模块开工时与用户讨论。

## 7. 合并模式（MG1–MG6）

> MG1–MG6 由用户 2026-10-17 全部按推荐确认（用户原话：「MG1–MG6 都按推荐走」），见 D65，关闭 K43。

### 7.1 已随 D64 定下的部分
- 模块切换器只在模块主页出现；进入二级页后顶栏换成「返回 + 标题」。
- 模块之间的高度差：~~改高时加一段短过渡（约 0.15 s）~~（已由 D66 取代：换页不加动画，量好高度后一次换完；面板设高度上限，内容区超出时滚动）。不取各模块最大高度（内存等短模块会留下大片空白）。
- 总览卡片点击后**替换**为该模块主页，不算一层，避免出现总览 → 模块 → 列表 → 详情四层。

### 7.2 MG1 合并 item 的组成与顺序
- 合并 item = 所有已开启的 widget 横向拼进一个 `NSStatusItem`，段与段之间用分隔（细线或留空，设置项）。每段沿用自己的宽度、颜色、排版与呈现形式；合并 item 的宽度是各段宽度加分隔之和，固定，不随数值变化。
- 顺序在设置的「菜单栏」页拖动调整（合并后无法在菜单栏上拖）。第一次切换到合并模式时，按切换那一刻各 widget item 在屏幕上的 x 坐标定初始顺序；拿不到坐标的 widget（溢出区等）排在后面，按模块顺序。
- widget 的开关仍在各模块页（D41），合并与否不改变开了哪些 widget；新开的 widget 追加到合并顺序末尾。
- 合并 item 的采样需求是各段需求的并集，规则与单 widget 模式相同。
- 不做「按模块各合并一个 item」。

### 7.3 MG2 点击合并 item（K43）
- 按点击的 x 坐标打开那一段所属模块的主页；点在分隔上归到最近的一段。拿不到坐标（坐标不在 item 窗口内，例如从溢出区打开）时打开总览。
- 面板已打开时的导航（D64 规则在合并模式下的对应）：
  - 再点同一段：在二级页时回到模块主页；在主页（或总览）时关闭面板。
  - 点另一段：原地切换到那一段所属的模块主页。
- 坐标来源：面板打开时沿用全局鼠标监视器里的 `NSEvent.mouseLocation`（单 widget 模式「点另一个 widget」已在用）；面板关闭时在 `didBegin` 回调里读 `NSEvent.mouseLocation`，实现时用探针确认它落在 item 窗口内。

### 7.4 MG3 切换器列出的模块
- 总览 + 全部 6 个模块，与是否开了 widget 无关；不可见的模块不采样。
- 顺序：合并 item 里出现的模块按它们在 item 中首次出现的顺序排在前，其余按 D53 的模块顺序（CPU、功耗、内存、存储、GPU、网络）跟在后。总览始终第一。

### 7.5 MG4 切换器样式
- 顶栏下单独一行分段控件（27 的 `.tabs` 角色），两个字的文字标签：总览 · CPU · 功耗 · 内存 · 存储 · GPU · 网络。7 段放进 332 pt。
- 只在模块主页和总览出现；进入二级页后，这一行与顶栏一起换成「返回 + 标题」。
- 面板为 key 窗口时 ⌘1–⌘7 切换（按切换器顺序）。
- 单 widget 模式维持 D47：没有切换器。

### 7.6 MG5 总览
- 每个模块一张定高小卡片（两行数值 + 60 s 迷你曲线），点卡片替换为该模块主页。最底下「最耗能的 3 个应用」卡片，点击打开应用活动窗口（应用活动上线前不显示）。
- 卡片列出的模块与切换器一致（MG3）。
- 数据只用各模块的常驻采集器（与 widget 同源）；总览可见时不扫 Top N、不读全部盘的 SMART、不读 CoreWLAN。开销按 D19 面板打开时低于 2% 实测。

| 卡片 | 第 1 行 | 第 2 行 | 曲线 |
|---|---|---|---|
| CPU | 总占用 | 按档占用（档名运行时取） | 占用 |
| 功耗 | 整机功率 | SoC 最热点 · 风扇 | 整机功率 |
| 内存 | 占用 | 压力 · 交换 | 占用 |
| 存储 | 盘温（盘温 widget 绑定的盘） | 读 / 写 · 可用空间 | 读写 |
| GPU | 活跃 | 功率 · 温度 | 活跃 |
| 网络 | 主接口 ↑ / ↓ | 接口名 · 今日流量 | ↑↓ |
| 应用 | 前 3 个应用的能耗 | — | — |

- 卡片内容暂不开放自选，P1 与「带变量的文本模板」一起考虑。

### 7.7 MG6 设置组织
- 「菜单栏」页（D41 容器页）新增：「合并为单个 item」开关；合并顺序列表（可拖动，只在合并模式下显示）；分隔样式（细线 / 留空）。
- 溢出区提示（D06）改为：已开启的 widget 较多时，建议切换到合并模式。
- 浮窗：合并模式下固定为浮窗后切换器照常可用；单 widget 模式维持 D47。

| 模块 | 改动 |
|---|---|

## 9. 偏离记录

### 2026-10-17（实现）
- **切换器用现有的 `SegmentedButtons`，不用 27 的 `.tabs` 分段控件**（§7.5 原写 `.tabs` 角色）：系统分段控件底层是 NSSegmentedControl，每次布局都要重新测量，在每秒刷新的面板里开销可观（CPU 模块偏离记录 2026-10-15）。外观同面板里其他分段按钮。
- **合并顺序用「左移 / 右移」按钮调整，不用拖动**（§7.7 原写「可拖动」）：设置页是 grouped `Form`，macOS 上 `onMove` 拖动排序不可靠。
- **「在应用活动中查看全部 ›」暂不显示**（§4）：应用活动上线时再加，同时加总览底部的「最耗能的 3 个应用」卡片（§7.6）。
- **「活跃」的判定**（§3）：最近 60 s 内任一方向超过 1 KB/s。「只看活跃」时没有活跃项则列出全部并给提示，不出现空列表。网络与存储各记一个开关（`network.panel.virtualActiveOnly`、`storage.panel.listActiveOnly`，默认开），旧键 `network.panel.showsVirtual` 不再读取；网络设置页原「展开虚拟接口」改为「虚拟接口列表只看活跃」。
- **虚拟接口列表按类型分组**（隧道、虚拟机、网桥……），组内按 index，不按速率排。
- **用户在菜单栏里移除合并 item 时退出合并模式**，不关掉任何 widget（各 widget 重新单独出现）。
- **应用详情页的成员数值列跟随入口模块**：GPU 没有按进程的公开计数，从 GPU Top N 进入时成员列 CPU。「按进程」分组和 coalition 不可用（同 uid 回退）时，Top N 行不能点进详情。
- **二级页的标题在顶栏**：存储单盘详情原来自带的「‹ 存储」按钮和标题行去掉，副标题（位置、接口、BSD 名、容量）成为页内第一行。
- **验证限制**：面板打开期间，合成点击（CGEvent）点在本 app 的菜单栏 item 上时全局鼠标监视器收不到（点菜单栏空白处能收到）。因此「合并 item 上点另一段原地换模块、点同一段回主页或关闭」只能由用户用真实点击验收；这与单 widget 模式「再次点击 item 关闭」走同一条路径，后者已用真实点击验收过。打开面板时按坐标选模块（`didBegin` 里读 `NSEvent.mouseLocation`）已用合成点击验证：点在 SYS 段打开「功耗与散热」。
- **启动参数**：新增 `--merged`（启动时打开合并模式）与 `--panel-route=virtual|external|raid`（推入二级页），截图与开销测量用；`make measure` 新增 `merged`、`overview` 两档。

### 2026-10-17（D66 实现）
- 换页统一走 `PanelController.changePage`：在一个关闭隐式动画的 `CATransaction` 里改状态、同步量高（`fittingSize` 能拿到刚改的状态）、改窗口大小。切换器、⌘1–⌘7、总览卡片、推入二级页（环境里的 `panelNavigate` 改由控制器执行）、返回按钮、Esc、再次点击 widget 回主页都走它。日志「面板改高：旧 → 新（上限）」每次换页只出现一次，没有下一轮补量，说明同步量高拿到的就是新内容。
- 模块内部的结构变化（`panelLayoutChanged`）仍在下一轮量高，但不再有动画。
- 高度上限写在 `PanelState.maxPanelHeight`，根视图 `.frame(maxHeight:)` 截住理想高度；内容区是一个 `ScrollView`（`scrollBounceBehavior(.basedOnSize)`），用「模块 + 路径」作 `id`，换页时回到顶部。`PanelSubpage` 只剩排版。
- 实测（M5 Pro，1080p，程序坞在下）：上限 951 pt；合并模式功耗页原 983 pt，现在封顶 951，顶边停在菜单栏下方（窗口 Y = 36），「能耗」卡片在内容区里滚动。
- 合并顺序核对：单 widget 模式下新开的 item 排在左边，本机菜单栏从左到右是「网速、盘温、内存、整机功率、CPU」，第一次合并记下的顺序与屏幕一致（MG1），切换器随之排序。
