# 电源设备模块验收报告

> 日期：2026-10-19。范围：D84（分支 `p1/power-devices`）。边界实测见 `power-devices-boundary.md`，规格与偏离记录见 `power-devices.md`。

## 结论（2026-10-19 用户验收通过）

- D84 列的内容已完成：
  - 数据：IOPS 设备清单（UPS、内置电池基础项、蓝牙配件，事件驱动）；UPS 的 HID 扩展遥测（负载与估算瓦数、输入 / 电池电压、状态位、额定值与阈值、自检结果、生产日期），用公开 IOHIDDevice，只读；
  - 界面：面板「电源」tab（无设备时在切换器里隐藏）、菜单栏「电源设备电量」widget（出厂关）、总览卡片、设置页、诊断页；
  - 历史：主 UPS 的电量、负载、输入电压每分钟；UPS 电池供电区间（schema 4）；导出写进 metadata；
  - CLI `devices`（`--watch` 供放电实测用）。
- 私有层新增两个符号（`IOPSCopyPowerSourcesByType`、`IOPSAccNotificationCreateRunLoopSource`），私有层版本 3。
- 偏离规格 9 处，见 `power-devices.md` §11（其中一处由 PD8 放电实测发现，已修，见 §3）。
- 2026-10-19 用户验收通过。验收中按用户要求的改动：菜单栏电池图形加充电闪电；UPS 卡去掉负载估算说明、「更多」默认展开；浮窗换页始终原地（D85，与本模块无关，随本分支合并）。
- §2 的开销疑点已用 4 对交替测量排除（本模块没有可测的增量）。

## 2. 开销（`docs/perf/power-devices.md`，D80 口径）

| 档位 | M5 | M4 |
|---|---|---|
| 出厂默认（widget 出厂关；后台多了电源设备历史：IOPS 60 s、HID 60 s） | 0.195–0.229%（4 次） | 0.102% |
| 面板打开（电源设备 tab，IOPS 1 s，HID 2 s） | 0.209% | 0.102%（无设备） |

- 预算：常驻 < 0.2%，面板打开 < 0.7%。面板档两台都在预算内；M4 出厂默认档与 10-18 的 1.0.0（0.099%）持平。
- M4 的测量经用户同意（2026-10-19）先结束了上面运行的 1.0.0 Release 实例（SIGTERM，正常收尾），测完后用 `open` 重新启动（D78）。
- **疑点**：出厂默认档与 `main`（1.0.0）交替测了 2 + 4 次：`main` 0.168%、0.195%，本分支 0.197%、0.200%、0.195%、0.229%，平均高约 0.02%（约 3 M 指令/s）。本机今天的波动也不小（同一份 `main` 两次差 0.027%）。
  - Release 构建的 60 s 对照采样（1 ms 一次）：非空闲样本 `main` 57、本分支 74，多出的样本散在主线程的 objc 消息、锁与 malloc 上，没有落在本模块的代码里；HID 读取与 IOPS 重建在采样里几乎看不到。
  - 已排除：HID manager 开着闲置（实测 20 s 不到 0.2 ms）；每分钟重开 HID（空闲关闭改为 180 s 后没有变化，改动保留）。
- **复测结论（2026-10-19 16:25–16:48，用户要求）**：与 `main` 交替再测 4 对（经临时 launchd 任务启动，跑完即删；会话内起的进程所在的 coalition 已超过 80 个成员，`ipsref` 的 coalition 自检不过）：

  | 对 | `main`（1.0.0） | 本分支 |
  |---|---|---|
  | 1 | 0.167%（17.9 M 指令/s） | 0.170%（18.1） |
  | 2 | 0.188%（20.4） | 0.202%（19.7） |
  | 3 | 0.233%（20.6） | 0.203%（19.6） |
  | 4 | 0.232%（20.4） | 0.242%（19.5） |
  | 平均 | 0.205%（19.8） | 0.204%（19.2） |

  两边没有差别，本模块在出厂默认档没有可测的开销增量；之前的 0.02% 是测量波动。另一方面，**同一份 1.0.0 今天在本机的出厂默认档平均也在 0.2% 上下**（10-18 测为 0.172%），说明 M5 出厂默认档离 D80 的预算本来就很近、受机器状态影响大。这与本模块无关，单独记下，供之后决定要不要处理。

## 3. PD8 放电实测（M5，2026-10-19 16:03）

用户拔掉 UPS 市电约 84 s 后插回（预定 ≤ 60 s，实际稍长；电脑由 UPS 供电，未断电）。`sysinfo-cli devices --watch` 全程记录，Debug 版同时运行（电源设备 widget 开、历史记录开）。

| 项目 | 结果 |
|---|---|
| 切换检测 | IOPS 与 HID 同时看到：HID 状态位 AC → 放电，输入 0 V，电池电压 27.3 → 23.4–23.9 V；恢复后 AC + 充电，输入 226 V |
| IOPS 通知频率 | 外接电源时每分钟约 2 次；由电池供电时约每 1.3 s 一次（每次 UPS 改写剩余电量与时间），1 s 去抖后快照每 1–1.5 s 重建一次 |
| UPS 自己的估算 | 电量 30 s 内由 100% 跳到 69%（按电池电压下陷估算），之后稳定；剩余时间 28 → 19 min；恢复市电后电量仍报 69%，开始充电 |
| 历史区间 | `ups_power_span` 记下 16:03:26–16:04:50（83.5 s），未标估计 |
| 发现的问题（已修） | IOPS 的 `Voltage` 由电池供电时是电池电压（24 V），恢复市电后 15 s 以上仍停在 26 V：面板会把它当成输入电压，HID 与 IOPS 的电压对照会误判。改为以 HID 为准，见 `power-devices.md` §11 |
| 未核实 | K20 的「UPS 放电降频」：ThrottleMonitor 的 info 级日志没有落盘，这次没能从日志里确认 5 s 去抖后的降频；它用的是同一份 IOPS 供电类型，代码路径没有改动 |
